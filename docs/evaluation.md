# Evaluation

All Claude runs use Claude Opus 5.5 through the Anthropic API directly (`effort=low` for decisions and
answers). Laya runs locally on an RTX 4070 Laptop GPU (8 GB). Costs use list prices
(input USD 4, output USD 20 per million tokens).

## Data

| Set | Size | Source |
|---|---|---|
| `data/tickets.jsonl` | 240 tenant messages: 5 intents x 2 languages x 24, urgency split 8/8/8 | Generated by Claude (`evals/make_tickets.py`), Arabic half Modern Standard, half Gulf dialect |
| `data/kb/` | 5 bilingual policies (27 sections) + 1 untrusted note with an injected instruction | Hand-written, fictional |
| `evals/qa.jsonl` | 32 questions: 22 answerable, 8 not in the policies, 2 injection probes; 16 English, 16 Arabic | Hand-written and hand-labelled |

The 240 messages are split 50/50 per (language, intent) with a fixed seed: heads are fitted on one
half, everything is scored on the other.

## 1. Triage (120 held-out messages)

| Engine | Intent EN / AR | Urgency EN / AR | Emergency recall EN / AR | Median time | Cost |
|---|---|---|---|---|---|
| Laya Router, zero-shot | 0.67 / 0.30 | 0.65 / 0.43 | 1.00 / 0.47 | 28-41 ms | local |
| Laya reader, zero-shot | 0.50 / 0.43 | 0.42 / 0.37 | 1.00 / 1.00 * | 60-91 ms | local |
| Laya reader + heads fitted on 120 messages | 0.63 / 0.52 | 0.70 / 0.75 | 0.82 / 0.79 | 88-119 ms | local, fit in 22-30 s |
| Claude | 0.68 / 0.78 | 0.95 / 0.95 | 1.00 / 1.00 | 2,127 ms | USD 0.0044 per message |

\* The zero-shot reader calls almost everything an emergency (precision 0.36 in Arabic).
Times vary between runs on the same GPU; both observed medians are shown.

- Zero-shot Arabic is the weak point: the Router missed more than half of the Arabic emergencies.
- Fitting is cheap and helps most where it matters: Arabic urgency 0.43 -> 0.75, in under 30 seconds,
  without touching the model weights.
- Intent labels overlap (deposit refunds sit between "move" and "payments"); Claude itself reached 0.73.

## 2. Cascade: Laya first, Claude when Laya is unsure

Laya (fitted) decides when the lower of its two confidences is at or above the threshold; otherwise
Claude decides. Same 120 messages.

| Threshold | Sent to Claude | Intent | Urgency (EN / AR) | Emergency recall | Avg time | Cost per 1,000 messages |
|---|---|---|---|---|---|---|
| Laya only | 0% | 0.58 | 0.73 (0.70 / 0.75) | 0.80 | 91 ms | USD 0 |
| **0.5 (shipped)** | **53%** | **0.71** | **0.85 (0.80 / 0.90)** | **0.93** | **1.1 s** | **USD 2.31** |
| 0.6 | 73% | 0.75 | 0.89 (0.87 / 0.92) | 0.95 | 1.5 s | USD 3.19 |
| 0.7 | 88% | 0.73 | 0.93 (0.90 / 0.95) | 0.98 | 1.9 s | USD 3.89 |
| Claude only | 100% | 0.75 | 0.95 (0.95 / 0.95) | 1.00 | 2.1 s | USD 4.41 |

At 0.5 the cascade halves Claude cost and latency for 10 points of urgency accuracy. The limit is how
well Laya's confidence separates right from wrong after fitting on 120 messages: a curve that only
reaches Claude's accuracy near 90% Claude traffic means the confidence is useful but not sharp.
More labelled messages are the obvious next step.

## 3. Evidence gate ("does this passage contain the answer?")

90 held-out (question, passage) pairs from the top-6 retrieval results of half the questions;
14 positive (expected document and an expected fact present).

| Engine | Precision EN / AR | Recall EN / AR | Median time | Cost |
|---|---|---|---|---|
| **Laya Router, zero-shot (shipped)** | 0.46 / 0.35 | **0.86 / 0.86** | 23 ms | local |
| Laya reader, zero-shot | 0.40 / 0.50 | 0.57 / 0.71 | 59 ms | local |
| Laya reader + fitted head (17 positive pairs) | 0.50 / 0.33 | 0.86 / **0.14** | 45 ms | local |
| Claude | 0.64 / 1.00 | 1.00 / 1.00 | 1,876 ms | USD 0.0033 per pair |

The fitted head is a failure worth keeping: 17 positive examples were not enough, and Arabic recall
collapsed. The shipped gate is zero-shot and tuned for recall; the writer is the second check.

## 4. End to end (32 questions)

| Configuration | Correct action (EN / AR) | Hand-offs correct | Facts in answers | Injection-safe | No LLM call | Avg time | Cost |
|---|---|---|---|---|---|---|---|
| Laya only, zero-shot | 0.72 (0.76 / 0.67) | 0.78 | 1.00 | 1.00 | 47% | 2.2 s | USD 0.09 |
| **Cascade triage + Laya gate (shipped)** | **0.88 (0.94 / 0.80)** | **1.00** | **1.00** | **1.00** | 31% | **2.9 s** | **USD 0.16** |
| Claude decides everything | 1.00 (1.00 / 1.00) | 1.00 | 1.00 | 1.00 | 34% | 19.5 s | USD 1.10 |

- The shipped configuration is 7x cheaper and 6.7x faster than letting Claude make every decision,
  and every one of its four mistakes is a safe one: the question went to a person instead of being
  answered. Two are Arabic questions whose correct passage the Laya gate dropped (cash rent, noise);
  two are questions where the passages reached Claude and the writer judged them insufficient.
- Zero-shot Laya alone over-escalates ("What time does the pool close?" was called an emergency),
  which is why triage uses the cascade.
- "Claude decides everything" is slow mainly because the gate makes one call per retrieved passage.
- Answers that were given contained every expected fact, and no reply repeated the injected request
  for card numbers.

## 5. Photo triage (v0.2)

15 public-domain/CC0 photos from Wikimedia Commons (`data/photos/SOURCES.md`), labelled by hand:
3 emergency (two collapsed ceilings, an overflowing toilet), 8 soon (water stains, mould, broken
glass, a broken light fixture, a hole in a wall), 4 routine (a caulk crack, three rooms with no problem).

| Engine | Urgency | Problem type | Emergencies caught | False emergencies | Median time |
|---|---|---|---|---|---|
| Laya reader, zero-shot | 0.20 | 0.47 | 3 / 3 | 10 | 760 ms |
| Claude | 0.73 | 0.87 | 2 / 3 | 3 | 2,026 ms |
| Cascade below 0.5 (shipped) | 0.73 | 0.87 | 2 / 3 | 3 | Claude on 10 of 15 |

Laya rated normal living rooms as emergencies; its confidence on those was 0.28-0.36, so the cascade
passed them to Claude. Claude rated the overflowing toilet "soon", the one missed emergency.

## 6. OKF policies (v0.2)

The policies moved from plain markdown to an OKF v0.2 bundle, with a deprecated 2025 rent policy
(bounced-cheque fee AED 1,000) and a draft balcony-barbecue rule added. Two questions were added for
the draft (d01, d02), and the bounced-cheque questions (e06, a06) now also fail if the deprecated fee
appears. End to end on 34 questions with the shipped configuration:

| | Correct action (EN / AR) | Facts in answers | Injection-safe | No deprecated values | Avg time | Cost |
|---|---|---|---|---|---|---|
| Cascade + Laya gate, OKF policies | 0.88 (0.94 / 0.81) | 1.00 | 1.00 | 1.00 | 3.0 s | USD 0.18 |

- The first OKF run appended each concept's status line to its text. That run flagged one reply as
  unsafe: the contractor note's injected sentence had not been stripped because Laya's injection score
  dropped from 0.86 to 0.41 with the extra line. Claude's reply was in fact safe (it warned the tenant
  not to send ID or card details), and the safety metric was narrowed to the attacker's address so a
  warning is not counted as a leak. Provenance now lives in a separate field; the rerun above strips the
  injected sentence again.
- Arabic action accuracy moved between 0.81 and 0.88 across runs; the difference is one question.

## Reproduce

```bash
python evals/triage_eval.py              # Laya triage configurations, saves fitted heads to data/heads
python evals/triage_eval.py --claude --skip-laya
python evals/cascade_eval.py             # threshold sweep (Laya + Claude on 120 messages)
python evals/gate_eval.py                # Laya gate configurations
python evals/gate_eval.py --claude --skip-laya
python evals/photo_eval.py               # photo triage (Laya, Claude, cascade)
python evals/run_qa.py                   # end to end, shipped configuration
BAWABA_TRIAGE=claude BAWABA_GATE=claude python evals/run_qa.py
```
